Base de Connaissances : Chronotime (Module GT - Habilitations et Workflow)
1. Concepts Fondamentaux et Architecture
Environnement : Chrono-Time module GT (Gestion des Temps).
Principes de gestion :
Le système gère des profils utilisateurs liés à des fiches collaborateurs.
Un utilisateur est inutilisable sans habilitations (profils, rôles, périmètres).
Configuration de navigation : Obligatoire pour toute connexion, sinon erreur d'authentification.
Hiérarchie des accès :
Profil utilisateur : Combinaison de fonctionnalités (actions autorisées).
Rôle : Regroupement de groupes de fonctionnalités.
Périmètres : Définissent les ressources (collaborateurs) accessibles.
Filtres : Définissent les données spécifiques accessibles au sein des ressources.
2. Gestion des Habilitations (Paramétrage)
Modèles (Astérisques) : Les profils/groupes préfixés par une astérisque (*) sont des modèles standards. Il est fortement déconseillé de les modifier directement. Il faut les dupliquer pour créer des versions spécifiques "Client".
Fonctionnalités :
Le "Gérer" est un prérequis pour voir les informations (ex: pour voir les horaires, il faut la fonctionnalité "Gérer les collaborateurs").
NA (Non Applicable) : Indique que les notions d'ajout, modification ou suppression ne s'appliquent pas à cette fonctionnalité.
Mise à jour post-patch : Les patchs n'écrasent pas les habilitations personnalisées. Les nouvelles fonctionnalités apportées par un patch doivent être ajoutées manuellement selon la procédure "Mise à jour manuelle des habilitations" (fournie par version).
3. Gestion des Filtres et Périmètres
Filtres : Associés à des entités fonctionnelles (ex: Absence, Horaire Journalier).
Comportement : L'ajout de plusieurs filtres sur une même entité déclenche une logique de type "OU" (cumul des résultats).
Entités Fonctionnelles : Il est crucial de choisir la bonne entité pour filtrer une fonctionnalité (ex: pour filtrer la saisie d'horaires exceptionnels, utiliser l'entité HoraireExceptionnel et non HoraireJournalier).
Périmètres Dynamiques : Permettent de gérer des populations variables (ex: "égal à mon élément d'affectation", "rattaché à mon élément d'affectation") sans créer des milliers de périmètres statiques.
4. Workflows et Circuits de Validation
Profil de Workflow : Distinct du profil utilisateur. Indique la casquette de l'utilisateur dans le circuit (ex: RESP, ADMIN, COLLAB).
Priorité des profils : Les profils autorisés dans un circuit sont lus par ordre de priorité décroissante (ADMIN > RESP2 > RESP > COLLAB). Si un utilisateur possède plusieurs profils, le système prend le plus haut niveau.
Notifications :
Les notifications par mail sont configurées dans les boîtes du circuit.
Par défaut : Les mails sont regroupés et envoyés en mode différé (ex: 22h30).
Mode immédiat : Nécessite une configuration spécifique dans la table YNF_MODELE (changement du groupe de mails et du déclencheur).
Relances automatiques : Gérées par les traitements de nuit.
5. Gestion des Événements et Calendriers
Calendrier : Définit les jours fériés et exceptionnels.
Priorisation des horaires :
Horaire exceptionnel (manuel).
Horaire de remplacement (type de jour du calendrier).
Horaire de référence (programme hebdomadaire/cycle).
Emploi du temps : Permet de générer des événements répétitifs (absences, activités) sur une période. Un emploi du temps doit être "Publié" pour être affectable.
6. Outils de Visualisation (Planning & Agenda)
Groupes de compteurs : Définissent les informations affichées dans les différents écrans. Le paramètre "Utilisé pour" est crucial pour déterminer l'emplacement (Vue journée, Planning, Agenda).
Personnalisation : Les préférences d'affichage (multiligne, colonnes) peuvent être enregistrées au niveau utilisateur ou général.
Saisie de masse : Mode de saisie en continu permettant d'enchaîner les événements sans repasser par le dossier collaborateur.
